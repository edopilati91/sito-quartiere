## Project

A neighbourhood website ("sito quartiere"), Italian-language, built on the Laravel 13 Livewire starter kit plus a Filament 5 admin panel. Served locally by Laravel Herd; SQLite by default.

The block inside `<laravel-boost-guidelines>` below is generated by Laravel Boost from `.ai/guidelines/*.md` and package guidelines, and `php artisan boost:update` (run on every `composer update`) overwrites it. Change project conventions in `.ai/guidelines/`, not inside that block. Edit only this section by hand.

## Commands

- `composer setup` — first install (deps, `.env`, key, migrate, `npm run build`)
- `composer dev` — runs `php artisan dev` (server, queue, logs, Vite)
- `npm run build` / `npm run dev` — assets via Vite+ (`vp`)
- `php artisan test --compact tests/Feature/Auth/AuthenticationTest.php` or `--filter=name` — single test
- `composer test` — what CI runs: Pint check, PHPStan, full Pest suite
- `composer analyse` — PHPStan (level 5, 100% type coverage required on `app/` and `database/`)
- `vendor/bin/pint --dirty --format agent` — format changed PHP files
- `composer rector` — Rector refactors
- `vendor/bin/filacheck --fix` — after touching `app/Filament`

## Architecture

Two separate UIs share the `User` model and the `web` guard:

- **Public site + user area** (`/`, `/dashboard`, `/settings/*`): Livewire 4 + Flux UI. Pages are single-file Livewire components in `resources/views/pages/` (the `⚡` prefix in filenames marks a component), routed with `Route::livewire('…', 'pages::settings.profile')` in `routes/web.php` and `routes/settings.php`.
- **Auth** is handled by Fortify (headless). Views and features are wired in `app/Providers/FortifyServiceProvider.php`; user creation and password reset logic live in `app/Actions/Fortify/`, with shared validation rules in `app/Concerns/`. Supports 2FA and passkeys.
- **Admin panel** at `/admin`: Filament, configured in `app/Providers/Filament/AdminPanelProvider.php`. Resources, pages and widgets are auto-discovered from `app/Filament/{Resources,Pages,Widgets}`.

App-wide defaults in `AppServiceProvider`: dates are `CarbonImmutable`, destructive DB commands are blocked in production, and strict password rules apply only in production.

Tests: Pest; `tests/Feature` uses `RefreshDatabase`.

Note: `lang/` does not exist yet. Run `php artisan lang:publish` before adding the first `lang/it/` and `lang/en/` keys. `APP_LOCALE` defaults to `en` in `.env.example`, even though the site is meant to be Italian.

### Database Structure

**Price fields:**
Every price field should be stored as an integer in the smallest unit (e.g., cents instead of euros).

**Enum fields:**
Use `enum` instead of `string` for enum fields:

$table->enum('status', EventStatus::values());

=== .ai/general-conventions rules ===

### Models

- **Singular, PascalCase**: `Event`, `News`
- **Pivot Models**: Descriptive names: `EventUser`
- **Polymorphic Models**: Single name: `Comment` (polymorphic commentable)

### Enums

- **Location**: `app/Enums/`
- **Values**: TitleCase: `Published`
- **Implementation**: Implement Filament's `HasLabel` interface, with translated labels
- **Comparisons**: compare enum instances (`$event->status === EventStatus::Published`), not `->value`.
  `->value` is correct only when passing values to raw DB queries (`->where(...)`, `->update(...)`).

### Strict Typing

All new PHP files must declare strict types:

```php
declare(strict_types=1);
```

### Eloquent Relationships with Type Hints and PHPDoc required

```php
/**
 * @return BelongsTo<User, $this>
 */
public function author(): BelongsTo
{
    return $this->belongsTo(User::class);
}
```

### Factory Pattern

```php
use Database\Factories\EventFactory;
use Illuminate\Database\Eloquent\Attributes\UseFactory;

#[UseFactory(EventFactory::class)]
class Event extends Model
{
    use HasFactory;
}
```

### Pivot Tables with Models

Always create explicit pivot models for complex relationships:

```php
public function participants(): BelongsToMany
{
    return $this->belongsToMany(User::class)
        ->using(EventUser::class)
        ->withPivot('registered_at');
}
```

### Translation Keys

All UI strings must use translation keys. The site is in Italian: add keys to `lang/it/` (and `lang/en/`).

```php
__('events.plural')      // "Eventi"
__('events.singular')    // "Evento"
__('shared.name')        // "Nome"
```

### Model creation and edit

When creating or editing a model in code, assign attributes one by one instead of passing an array.
Do not use `Model::create([array])`, use:

```php
$model = new Model();
$model->field = $value;
$model->save();
```

This is more readable and maintainable, and the static analyser and IDE support it better.

## Development Workflow

### When Adding New Entities

1. **Create the Model** in `app/Models` with `HasFactory` (always) and `SoftDeletes` (if needed)
2. **Create Supporting Files**: factory, migration, enum for status fields, seeder if useful
3. **Create the Filament Resource**:
   ```bash
   php artisan make:filament-resource [Name] --generate
   ```
4. **Add Translations** in `lang/it/` and `lang/en/`
5. **Write Tests** in `tests/Feature/`

## Common Mistakes to Avoid

1. **Don't use `env()` outside config files** - Use the `config()` helper
2. **Don't create relationships without type hints** - Always add PHPDoc
3. **Don't use deprecated Tailwind utilities** - Use v4 syntax
4. **Don't skip translation keys** - All UI strings must be translatable
5. **Don't create pivot tables without models** - Use explicit pivot models for complex relationships
6. **Don't forget to eager load** - Prevent N+1 queries
7. **Don't use `dayOfWeek` but `dayOfWeekIso`** - The week starts on Monday
8. **Don't store prices as float** - Use integers in cents

## When you find a bug

1. Write a test that reproduces the bug
2. Fix the bug
3. Run the test to ensure it passes

## After Implementation

After every implementation, run `composer analyse` and fix any issues.
